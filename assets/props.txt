# The prop catalogue.
#
# Everything the engine needs to know about a kind of entity that is not a
# player, in a file both the server and the client read. Adding a prop is
# editing this file and naming it from a map's Lua -- no C++, no JavaScript, and
# nothing to recompile on either side.
#
# TWO RECORD TYPES, because two different programs need two different halves and
# neither should have to understand the other's:
#
#   prop   <id> <name> radius <r> height <h> [solid] [usable]
#           The SIMULATION's half. The server reads it. `radius` and `height`
#           are the cylinder an agent has to be inside to touch the thing;
#           `solid` means a body cannot walk through it, and `usable` means
#           pressing use while facing it is reported to the script.
#
#           A prop with neither flag is a trigger volume you walk into -- a key,
#           a checkpoint. With `solid` it is an obstacle. With `usable` it is
#           something you press. They compose: a lever on a plinth is both.
#
#   sprite <id> size <world-height> [billboard] [state <n>] [fps <f>] frames A,B,C
#   mesh   <id> model <name> [state <n>] [clip <name>]
#           The RENDERER's half. The client reads it; the server never looks.
#           A kind may have several state lines, one per animation state, and
#           the server declares the STATE while the client owns the timing
#           (design §4) -- a sprite swaps frames on its own clock and a mesh
#           cross-fades on its own.
#
# Both parsers ignore records they do not understand, so a visual-only addition
# does not need the server restarted and a physics-only one does not need the
# assets rebuilt.
#
# `id` is explicit and never positional: two files that happened to list props
# in a different order would otherwise silently swap them.

# --- Doom keycards and skull keys -------------------------------------------
#
# Doom's keys are 8-unit-radius sprites that bob in place; at 1/48 scale that is
# 0.167, widened here to 0.35 because a pickup you have to stand exactly on is a
# pickup nobody picks up. The sprite names are the WAD's own lumps, extracted by
# tools/wad/extract_sprites.js.

prop 1 key_blue   radius 0.35 height 0.6
sprite 1 size 0.35 billboard state 0 fps 6 frames BKEYA0,BKEYB0

prop 2 key_yellow radius 0.35 height 0.6
sprite 2 size 0.35 billboard state 0 fps 6 frames YKEYA0,YKEYB0

prop 3 key_red    radius 0.35 height 0.6
sprite 3 size 0.35 billboard state 0 fps 6 frames RKEYA0,RKEYB0

prop 4 skull_blue   radius 0.35 height 0.6
sprite 4 size 0.35 billboard state 0 fps 6 frames BSKUA0,BSKUB0

prop 5 skull_yellow radius 0.35 height 0.6
sprite 5 size 0.35 billboard state 0 fps 6 frames YSKUA0,YSKUB0

# --- an obstacle, and a thing you press --------------------------------------
#
# Neither is placed by any map yet; they are here because the catalogue is the
# documentation for what a prop can be, and a format with no example of its own
# features is a format nobody uses them from.
#
# A barrel is solid: you walk into it and stop. Doom's own explodes, which is a
# script's decision -- on_prop_use and on_touch are where that would live.

# Doom's barrel is a 10-unit radius, 42-unit tall solid thing that explodes when
# hit. At 1/48 that is 0.21 and 0.875. Two states, and the SERVER declares which
# -- state 1 is the explosion, and how fast it plays is the client's business.

prop 10 barrel radius 0.21 height 0.875 solid
sprite 10 size 0.875 billboard state 0 fps 2 frames BAR1A0,BAR1B0
sprite 10 state 1 fps 14 frames BEXPA0,BEXPB0,BEXPC0,BEXPD0,BEXPE0

# A wall switch you press rather than a wall you press. Two states, and the
# server declares WHICH -- the client decides how fast it plays.

prop 11 lever radius 0.4 height 1.0 solid usable
sprite 11 size 1.0 billboard state 0 fps 0 frames SW1BRNGN
sprite 11 state 1 fps 0 frames SW2BRNGN
