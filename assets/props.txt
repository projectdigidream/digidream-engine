# The prop catalogue.
#
# Everything the engine needs to know about a kind of entity that is not a
# player, in a file both the server and the client read. Adding a prop is
# editing this file and naming it from a map's Lua -- no C++, no JavaScript, and
# nothing to recompile on either side.
#
# TWO RECORD TYPES, because two different programs need two different halves and
# neither should have to understand the other's:
#
#   prop   <id> <name> radius <r> height <h> [speed <s>] [solid] [usable]
#           The SIMULATION's half. The server reads it. `radius` and `height`
#           are the cylinder an agent has to be inside to touch the thing;
#           `solid` means a body cannot walk through it, and `usable` means
#           pressing use while facing it is reported to the script. `speed` is
#           world units per second for anything that walks, and becomes the
#           entity's move_speed -- a replicated parameter, so a slow monster is
#           slow on every client without a word of it crossing the wire. Absent
#           means the engine's default.
#
#           A prop with neither flag is a trigger volume you walk into -- a key,
#           a checkpoint. With `solid` it is an obstacle. With `usable` it is
#           something you press. They compose: a lever on a plinth is both.
#
#   sprite <id> size <world-height> [billboard] [state <n>] [fps <f>] frames A,B,C
#   mesh   <id> model <name> [state <n>] [clip <name>]
#           The RENDERER's half. The client reads it; the server never looks.
#           A kind may have several state lines, one per animation state, and
#           the server declares the STATE while the client owns the timing
#           (design §4) -- a sprite swaps frames on its own clock and a mesh
#           cross-fades on its own.
#
# Both parsers ignore records they do not understand, so a visual-only addition
# does not need the server restarted and a physics-only one does not need the
# assets rebuilt.
#
# `id` is explicit and never positional: two files that happened to list props
# in a different order would otherwise silently swap them.

# --- Doom keycards and skull keys -------------------------------------------
#
# Doom's keys are 8-unit-radius sprites that bob in place; at 1/48 scale that is
# 0.167, widened here to 0.35 because a pickup you have to stand exactly on is a
# pickup nobody picks up. The sprite names are the WAD's own lumps, extracted by
# tools/wad/extract_sprites.js.

prop 1 key_blue   radius 0.35 height 0.6
sprite 1 size 0.35 billboard state 0 fps 6 frames BKEYA0,BKEYB0

prop 2 key_yellow radius 0.35 height 0.6

# --- an obstacle, and a thing you press --------------------------------------
#
# Neither is placed by any map yet; they are here because the catalogue is the
# documentation for what a prop can be, and a format with no example of its own
# features is a format nobody uses them from.
#
# A barrel is solid: you walk into it and stop. Doom's own explodes, which is a
# script's decision -- on_prop_use and on_touch are where that would live.

# Doom's barrel is a 10-unit radius, 42-unit tall solid thing that explodes when
# hit. At 1/48 that is 0.21 and 0.875. Two states, and the SERVER declares which
# -- state 1 is the explosion, and how fast it plays is the client's business.

prop 10 barrel radius 0.21 height 0.875 solid
sprite 10 size 0.875 billboard state 0 fps 2 frames BAR1A0,BAR1B0
sprite 10 state 1 fps 14 frames BEXPA0,BEXPB0,BEXPC0,BEXPD0,BEXPE0

# A wall switch you press rather than a wall you press. Two states, and the
# server declares WHICH -- the client decides how fast it plays.

prop 11 lever radius 0.4 height 1.0 solid usable
sprite 11 size 1.0 billboard state 0 fps 0 frames SW1BRNGN
sprite 11 state 1 fps 0 frames SW2BRNGN

# --- enemies -----------------------------------------------------------------
#
# An enemy is an AGENT, not a prop: it walks, falls, steps up, slides along
# walls and is stopped by doors, and all of that is the controller a player
# already runs. It is drawn from these records all the same, because "what a
# thing looks like" is one question whether the thing moves or not.
#
# Doom's own sizes: a zombieman is a 20-unit radius, 56 tall; an imp the same.
# At 1/48 that is 0.417 and 1.167.
#
# ANIMATION STATES, declared by the server and timed by the client (design §4):
#   0 idle   1 walk   2 attack   3 pain   4 die
#
# Only the front-facing sprite of each frame is used. Doom stores eight angles
# per frame and picking one by the viewer's bearing is a renderer feature this
# does not have yet -- so an imp seen from behind looks like an imp seen from
# the front. Stated rather than left to be discovered.

# Doom's own speeds, converted: a monster moves N map units per tic at 35 Hz,
# which at 1/48 scale is N * 35 / 48 world units per second. A zombieman and an
# imp both move 8 -- 5.83 -- and a demon moves 10.
prop 20 zombieman radius 0.417 height 1.167 speed 5.83 solid
sprite 20 size 1.167 billboard state 0 fps 0  frames POSSA1
sprite 20 state 1 fps 6  frames POSSA1,POSSB1,POSSC1,POSSD1
sprite 20 state 2 fps 5  frames POSSE1,POSSF1
sprite 20 state 3 fps 0  frames POSSG1
sprite 20 state 4 fps 8  frames POSSH0,POSSI0,POSSJ0,POSSK0,POSSL0,POSSM0

prop 21 imp radius 0.417 height 1.167 speed 5.83 solid
sprite 21 size 1.167 billboard state 0 fps 0  frames TROOA1
sprite 21 state 1 fps 6  frames TROOA1,TROOB1,TROOC1,TROOD1
sprite 21 state 2 fps 5  frames TROOE1,TROOF1,TROOG1
sprite 21 state 3 fps 0  frames TROOH1
sprite 21 state 4 fps 8  frames TROOI0,TROOJ0,TROOK0,TROOL0,TROOM0

# The imp's fireball. A prop rather than an agent: it has no controller, it does
# not walk, and what it needs is a straight line and something to hit.
prop 22 fireball radius 0.13 height 0.26
sprite 22 size 0.4 billboard state 0 fps 10 frames BAL1A0,BAL1B0
sprite 22 state 1 fps 12 frames BAL1C0,BAL1D0,BAL1E0

# --- transient effects -------------------------------------------------------
#
#   vfx <kind> tracer [colour <hex>] [width <w>] [life <seconds>]
#
# Fire and forget, off the entity path: a tracer has no identity and nothing
# refers to it. The engine reports "effect 1 happened here, pointing that way";
# what a 1 IS lives here, which is what makes it customisable without touching
# either binary.

# Wide enough and slow enough to actually SEE.
#
# These were 0.035 wide and lasted a tenth of a second, which at 1/48 Doom
# scale is a sub-pixel line for about six frames -- correct, drawn, and
# invisible, which is indistinguishable from broken and was reported as such
# three times. A tracer is not a simulation object: nothing collides with it and
# nothing depends on its size, so the only question it has to answer is whether
# a person can tell a shot was fired. These are the numbers to turn down if they
# turn out to be gaudy, and turning them down needs no recompile.
vfx 1 tracer colour ffee88 width 0.09 life 0.35
vfx 2 tracer colour ff8844 width 0.12 life 0.45
